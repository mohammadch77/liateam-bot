# تست بار فروشگاه

اسکریپت: `shop/scripts/load-test.mjs` (بدون وابستگی؛ `fetch` خود Node با چند اتصال هم‌زمان). فقط درخواست GET می‌فرستد.

## سناریوها (به نسبت وزن، تصادفی)

| سناریو      | آدرس                                     | وزن |
| ----------- | ---------------------------------------- | --- |
| `home`      | `/`                                      | ۳   |
| `shopPrice` | `/shop?min=…&max=…` (فیلتر قیمت)         | ۲   |
| `product`   | یکی از ۲۰ محصولِ لینک‌شده در صفحه‌ی اصلی | ۴   |
| `search`    | `/search?q=…` (کرم، سرم، ریمل، …)        | ۱   |
| `suggest`   | `/api/search/suggest?q=…`                | ۳   |

## آستانه‌ها (هر سناریو جدا؛ بیشتر = اسکریپت با کد ۱ تمام می‌شود)

| سناریو      | p95 (میلی‌ثانیه) | نرخ خطای مجاز |
| ----------- | ---------------- | ------------- |
| `home`      | ۸۰۰              | ۱٪            |
| `shopPrice` | ۱۰۰۰             | ۱٪            |
| `product`   | ۸۰۰              | ۱٪            |
| `search`    | ۱۰۰۰             | ۱٪            |
| `suggest`   | ۳۰۰              | ۱٪            |

«خطا» یعنی هر پاسخی غیر از ۲xx (بعد از دنبال کردن ریدایرکت) یا قطع اتصال. عددها برای سرورِ فروشگاه است، نه لپ‌تاپ توسعه.

## اجرا روی staging (از لپ‌تاپ، از راه تونل SSH)

پنجره‌ی اول (تونل به خود فروشگاه؛ بدون nginx، TLS و Basic Auth):

```bash
ssh -p 9011 -N -L 3861:127.0.0.1:3861 root@193.242.208.208
```

پنجره‌ی دوم، در پوشه‌ی `shop/`:

```bash
npm run load-test -- http://127.0.0.1:3861 --duration 60 --connections 10
```

گزینه‌ها: `--duration <ثانیه>` (پیش‌فرض ۳۰)، `--connections <n>` (پیش‌فرض ۱۰)، `--only home,product`، و برای تست از پشت nginx: `--auth client:<رمز>` (در هدر فرستاده می‌شود، نه در آدرس).

**پیشنهاد ترتیب:** ۱۰ اتصال / ۶۰ ثانیه ← اگر سبز بود ۲۵ اتصال / ۶۰ ثانیه. هم‌زمان روی سرور `systemctl status avina-shop --no-pager | grep -E 'Memory|CPU'` و `top` را ببینید؛ اگر سایت‌های دیگر کند شدند، متوقف کنید. هرگز در ساعت پربازدید سایت‌های دیگر اجرا نکنید.

## نتیجه‌ی محلی (مرجع، نه معیار)

لپ‌تاپ توسعه (ویندوز، دیتابیس Docker، هم‌زمان با تست‌ها)، ۸ اتصال، ۲۰ ثانیه: حدود ۲۰ درخواست در ثانیه، خطا ۰٪؛ p95: صفحه‌ی اصلی ۶۴۱، فیلتر قیمت ۵۷۹، محصول ۹۰۳ (بالاتر از ۸۰۰)، جست‌وجو ۶۴۰، پیشنهاد ۲۱۳ میلی‌ثانیه. صفحه‌ی محصول برای هر درخواست کامل ساخته می‌شود (حالت کاربر در هدر)؛ اگر روی سرور هم از ۸۰۰ بیشتر شد، قدم بعدی کش کردن بخش ثابت صفحه‌ی محصول است.
